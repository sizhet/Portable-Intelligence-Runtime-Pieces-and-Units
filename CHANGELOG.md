# Changelog

All notable changes to **Portable Intelligence Runtime Pieces and Units (PIRP/PIRU)** will be documented in this file.

## [1.0.0] — 2026-09-16

### Initial Public Research Release

First complete release of the **Portable Intelligence Runtime Pieces and Units (PIRP/PIRU)** framework.

This release develops Portable Intelligence from the runtime level through publishing, unresolved intelligence, relay, Relay Localization, Collective Learning, and Computational Growth.

### Added — Core Framework

Introduced **PIRP — Portable Intelligence Runtime Piece** as a discovery-oriented abstraction for bounded-enough runtime intelligence that can potentially be:

* identified,
* carried,
* published,
* localized,
* continued,
* executed,
* observed,
* validated,
* composed,
* relayed,
* and grown.

Introduced **PIRU — Portable Intelligence Runtime Unit** as the more formalized engineering form of Portable Intelligence with clearer:

* identity,
* boundary,
* type,
* interface,
* runtime contract,
* validation,
* policy,
* version,
* and lifecycle.

Established the PIRP/PIRU duality:

```text
PIRP
=
Discovery-Oriented Portable Intelligence Piece

PIRU
=
Formalized Portable Intelligence Unit
```

### Added — Pre-Categorical Intelligence

Introduced the **Pre-Categorical Intelligence Hypothesis**:

> **Intelligence may exist as actionable, adaptive, composable, and growing runtime structure before it is classified into human-designed computational categories.**

Established the principle:

> **Intelligence precedes its computational classification.**

Distinguished computational perspectives such as:


### Added — Portable Intelligence

Expanded portability beyond conventional software portability.

Defined four portability levels:

```text

        |
        v

        v

        |
```

Established the stronger Portability Test:

> **Can another intelligence receive this piece, localize it into its own Known-Knowledge, continue its computation, and grow from where the previous intelligence stopped?**

Introduced:

> **A PIRP is not merely portable across runtimes; it may be portable across intelligences.**

## Design Boundary — v1.0.0

This release intentionally focuses on the conceptual and structural framework.

It does **not** define a mandatory:

```text
Java Runtime
Agent Framework
Network Protocol
Central Registry
Database Schema
Serialization Format
Global Capability Score
Universal PIRP Type System
```

No canonical Java demo or runtime implementation is included in v1.0.0.

This boundary is intentional.

The first release establishes:

```text
What is Portable Intelligence?

What distinguishes PIRP from PIRU?

How can unresolved intelligence be portable?

What is Relay?

Why is Relay Context intelligence?

How can intelligence be localized toward its next relay?

How can Collective Learning preserve growth history?

How can these structures evolve toward
Computational Growth Intelligence?
```

before selecting a specific implementation architecture.

## Canonical v1.0.0 Principles

The initial release establishes the following principles:

> **Intelligence precedes its computational classification.**

> **Preserve emerging intelligence before forcing complete formalization.**

> **PIRP protects discovery; PIRU supports engineering.**

> **Piece means bounded intelligence identity, not necessarily smallness.**

> **A PIRP may be portable across intelligences, not only across runtimes.**

> **A well-formed problem can itself be executable intelligence.**

> **A validated failure can be positive intelligence.**

> **Publish can be an intelligence-transfer operation.**

> **Relay is continued computation across an intelligence boundary.**

> **The Relay Event is itself an intelligence object.**

> **The path of intelligence growth is itself intelligence.**

> **Social Proximity is not Intelligence Proximity.**

> **Localization can search for where intelligence can productively continue growing.**

> **Capability and permission should remain distinguishable.**

> **Every relay can teach the system how to relay better next time.**

> **Collective Learning includes both Knowledge Growth and Relay Intelligence Growth.**

> **No participant needs to join the whole intelligence system. Each participant only needs to pick up one PIRP.**
